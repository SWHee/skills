# 검증 기록

2026-09-28, 가상 입력으로 독립 에이전트의 실제 출력과 구조·시간 계산을 검토했습니다.
아래 평가는 한 번의 행동 검증이며 실제 사용자의 발화 시간이나 모든 생성 결과를 보장하지 않습니다.

## 초기 비교와 보완

스킬 없이 B와 같은 짧은 입력으로 실행한 초기 결과는 완료·추정 상태를 대체로 유지했으나,
제목에 `어떻게 해결하였나? 또는 어떻게 해결할 예정인가?`를 그대로 출력했습니다.
또한 글자 수를 세지 않고 `예상 시간: 약 140~160초`를 표시했고, 인사·마무리가 지정 문구와 달랐습니다.
이에 제목 분기, 기본 인사·마무리, 전체 낭독 본문 계수와 재계산 절차를 명시했습니다.

자료 스킬의 첫 부분 수정 검증에서는 두 번째 주제를 바꾼 뒤 상단 요약에 예전 계획이 남았습니다.
확정 범위를 임의로 고치는 대신 같은 자료 안의 불일치 위치도 알리도록 보완했습니다.

## 자동 검사

- 플러그인 manifest 검증 통과.
- 두 SKILL.md의 frontmatter·이름·미완성 표식 검사 통과.
- 시간 계산: 750자 → 기본 151.4초, 느린 가정 170초.
- 공백·문장부호 제외, 발음 표기 입력, 빈 본문 거부 확인.
- 느린 가정 800자 = 180초, 801자 > 180초 경계 확인.
- `git diff --check` 통과.

## 행동 검증

실제 출력과 입력은 [behavioral-outputs.md](behavioral-outputs.md)에 보관합니다.

| 사례 | 관찰 결과 |
| --- | --- |
| A: 많은 기록·주제 미정 | 6개 후보로 묶고 영향·협업 중심 3개 추천, 선택 대기 |
| B: 미해결 포함·최종본 | 선정 질문 생략. 로컬 5건/배포 전, 캐시 추정/미재현, null 합의 전을 양쪽에 보존 |
| C: 일부 수정(이전 검증) | 개별 실행 결과만 저장됨. 당시 동일성 assert 및 전체본이 없어 재현 불가. 최신 자료를 거치는 연결 검증으로는 인정하지 않음 |
| D: 자료 없음 | 기준 발표 자료 요청, 스크립트 임의 생성 없음 |
| E: 발표자 변경·단일 주제 | 7팀 백엔드 민수와 마무리 일치, 한 주제 유지, 테스트·배포 전 보존 |
| F: 이전 연결 경로 | 기본 107.9초/느린 가정 122.2초: 시간 목표 미달. 별도 상세자료 직접 입력만 143.0초/160.8초 |

B는 269자(63.9초/73.8초), C 전체는 285자(66.8초/77.0초), E는 109자(34.8초/41.8초)였습니다.
이 짧은 사례들은 2분 목표 미달입니다. 근거 없는 설명으로 늘리지 않고 미달 이유를 표시하는 동작을 확인했습니다.

F는 별도 가상 근거를 주제별 20줄씩 제공했습니다. 상세 기록 전체는 인사 없이도 기본 192.3초였으며,
선별된 본문은 704자, 143.0초였습니다. 기본 낭독에는 인사·전환·마무리가 포함되고 질의응답용 메모는 제외됩니다.
초기 본문은 642자/131.7초여서 자료 내 설명을 보충한 뒤 다시 계산했습니다.

F의 첫 자료 파일은 세부 기록을 전부 붙여 화면용 간결성 기준을 충족하지 못했습니다.
이 파일을 자료 스킬의 성공 산출물로 판정하지 않고, 사용자 제공 상세자료를 가정한 스크립트 검증 입력으로 구분했습니다.

긴 기록에도 항목별 1~3문장을 적용하고 세부 절차를 통째로 붙이지 않도록 자료 스킬을 보완했습니다.
간결 자료를 다시 작성하고 그 자료만으로 새 스크립트를 생성했습니다. 양쪽의 사실·상태는 일치했습니다.
이 연결 결과는 511자, 기본 107.9초/느린 가정 122.2초로 목표보다 짧습니다.
704자/143초 결과는 사용자 제공 상세자료 기반 검증이며, 간결 자료 기반 결과와 구분합니다.
자료가 짧으면 2분 이상 분량을 보장하지 않으며, 내용을 늘리려면 사용자가 추가 근거를 제공해야 합니다.


## 적대적 검토 판단과 개선 후 재현

첫 지적은 채택하되 범위를 한정했습니다. 화면 요약에서 빠진 근거가 스크립트에 전달되지 않는 규칙과
107.9초 연결 결과는 실제 결함 근거입니다. 다만 원본 192.3초에는 반복 절차도 있으므로 그 길이만으로
유용한 근거 충분을 증명하거나 모든 1~3문장 자료가 실패한다고 일반화할 수는 없습니다.
원본 직접 사용 허용은 사용자의 ‘자료에 없는 사실 추가 금지’와 충돌하므로 채택하지 않았습니다.
대신 자료에 출처가 있는 발표자 메모를 별도로 남겨, 화면 가독성과 자료 기반 스크립트 원칙을 함께 유지합니다.

두 번째 지적의 목표 하한·갱신 순서·재현 근거·표시 오류는 채택했습니다. 발음 자동 추론은
산술 도구의 책임으로 추가하지 않았습니다. 입력이 실제 발음 사본인지와 전체 본문에 대응하는지는
저장된 원문과 명시적 변환표로 검사하고, 그 발음 자체의 적절성은 읽고 확인합니다.

[connected-case.json](connected-case.json)은 개발 에이전트가 기존 F 입력과 출력으로 수동 재현한 사례입니다.
원본 → 화면 본문 + 출처별 메모 → 낭독문 순서로 근거를 대조했습니다. 독립 모델 재실행이 아닙니다.
메모에는 화면에서 생략된 확인표, 논의 예시의 성격, 사용자 영향 미판단 등 원본 사실만 포함했습니다.
낭독문의 각 주장은 화면 또는 메모에서 확인했고, 추정·미재현·배포 전·합의 전을 유지했습니다.

| 저장된 연결 재현 | 글자 수 | 기본 추정 | 느린 가정 | 판정 |
| --- | ---: | ---: | ---: | --- |
| 자료+메모 기반 스크립트 | 704 | 143.0초 | 160.8초 | 시간 목표 충족 |
| 두 번째 주제 갱신 후 전체 스크립트 | 705 | 143.2초 | 161.0초 | 시간 목표 충족 |

부분 수정은 먼저 자료의 두 번째 주제와 해당 메모를 갱신한 뒤 스크립트에 적용했습니다.
상단 요약은 확정 범위여서 보존하고 실제 충돌 위치를 안내했습니다. 이미 바뀐 본문을 미수정이라고 안내하지 않습니다.
두 버전의 전체 자료·낭독문·발음 사본을 저장했습니다. `python3 weekly-brief/tests/test_connected.py`로
시간 하한·상한, 발음 사본 대응, 인사/마무리 포함, 지정 주제 밖 글자 단위 동일성을 재검사할 수 있습니다.
이 검사는 저장된 결과의 회귀 검사이며 미래 모델의 생성 품질이나 한국어 의미·발음의 자동 검증이 아닙니다.
짧은 B/E는 근거 부족 예외 검증으로 유지하며 2~3분 달성 사례로 세지 않습니다.
