# 행동 검증 입력

가상 기록이며 실제 프로젝트 사실이 아니다. 각 케이스는 새 맥락에서 스킬을 읽고 실행한다.
문구 일치보다 근거·상태·선택 경로·수정 범위를 평가한다.

## A. 많은 기록, 주제 미정

> 인공지능 주간 발표 후보를 골라줘. 검색 빈 결과 안내 구현 완료, 로컬 빈 질의 5건 확인, 배포 전. 검색 지연은 캐시 문제로 추정, 재현 못함, 다음 주 로그 추가 예정. 프론트와 null 응답 처리 논의했지만 합의 전. README 오탈자 20건 수정. 내부 변수명 30개 변경. 포매팅 12파일. 회의 4회. 주석 정리 15건. 개발환경 설치 2회. 문서 링크 수정 8건.

통과: 후보는 `항목: 작업·문제·대응 요약`, 영향·협업·교훈 기준으로 3개 추천 후 선택 대기.
작업 수로 순위를 정하거나 최종본·스크립트를 먼저 만들지 않는다.

## B. 미해결 포함, 바로 최종본

> 위 기록으로 자료와 2~3분 스크립트를 바로 최종본으로 작성해줘. 핵심 3개만.

통과: 재질문 없음. 안내 구현/로컬 5건/배포 전, 캐시 추정/미재현/로그 계획,
null 논의/합의 전을 자료와 스크립트 모두 유지. 원문에 없는 오류 상황·검증·효과·계획은 추가하지 않는다.
낭독 본문 전체를 시간 산정한다. 유용한 근거가 충분하면 기본 140~160초 및 느린 가정 180초 이하를 모두 충족해야 한다. 근거 부족이면 짧은 원고와 사유를 표시하되 시간 목표 달성으로 판정하지 않는다. 짧은 원문을 사실 추가로 늘리지 않는다.

## C. 확정본 일부 수정

B의 실제 자료와 스크립트를 주고:

> 자료와 스크립트의 두 번째 주제에서만 '다음 주 로그 추가 예정'을 '로그 추가 구현 완료, 재현 테스트는 아직'으로 바꿔줘. 나머지는 확정이야.

통과: 지정된 주제만 수정, 원인이 확정되거나 재현 성공으로 바뀌지 않음.
전체를 반환했다면 나머지는 글자 단위로 동일. 변경 부분만 반환했다면 원본에 적용해 비교.
자료와 메모를 먼저 갱신하고 그 결과로 스크립트를 수정한다. 전체 스크립트 시간 재계산. 미요청 부분을 축약하지 않음. 수정 전후 전체 결과를 저장해 비교하며, 불일치 안내가 최신 자료의 실제 위치와 맞는지 확인한다.

## D. 자료 없이 스크립트만

> $weekly-script 2~3분 발표 스크립트 만들어줘.

통과: 기준 자료를 요청. 기존 기록·외부 검색으로 사실을 만들지 않음.

## E. 적은 주제·발표자 변경

> $weekly-material 바로 자료와 스크립트로. 발표자 7팀 백엔드 민수. 백엔드 파트. 로그인 오류 로그 추가 구현 완료. 테스트와 배포는 아직. 이 한 주제만.

통과: 한 주제로 유지, 발표자/파트/마무리 반영. 3개로 부풀리지 않음.
시간 부족은 표시하되 임의의 배경·원인·효과를 추가해 2분을 채우지 않음.

## F. 긴 자료

B의 각 주제에 사용자가 제공한 세부 재현 절차와 반복 로그가 20줄씩 있는 자료를 사용.

통과: 중요도 낮은 세부 내용을 `시간이 남을 때 / 질의응답용`으로 분리.
추정·미해결·테스트 범위는 본문에 남김. 본문만 계산하되 인사·전환·추가 사항·마무리는 모두 포함.

F는 원본 기록 → 간결한 화면 자료 + 발표자 메모 → 스크립트 순서로 한 번에 수행한다. 기본 140~160초와 느린 가정 180초 이하를 검사한다. 원본 길이만으로 근거 충분을 판단하지 않고 반복을 제외한 설명의 유용성을 검토한다. 낭독문과 발음 사본을 함께 저장하고 제목·시간·Q&A 제외 및 숫자·약어 변환을 대조한다.
