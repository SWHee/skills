# 주간 발표 스크립트

사용자가 제공하거나 이 작업에서 작성한 최신 발표 자료를 기준으로 자연스러운 한국어 낭독문을 만든다. 원본 자료를 바꾸지 않는다. 자료가 없으면 요청한다. 기록에서 자료 작성까지 요청했다면 [weekly-material](../weekly-material/SKILL.md)을 먼저 적용한다.

자료에 붙은 `발표자 메모 — 화면 공유 제외`도 근거에 포함한다. 주제·완료 상태는 최신 화면 본문에 맞추고, 메모는 같은 주제의 설명을 보충할 때만 쓴다. 둘이 충돌하면 임의로 선택하지 말고 충돌 위치를 알린다. 원본 기록에만 있는 사실을 바로 가져오지 않는다. 연결 작성에서는 weekly-material이 원본 근거를 메모에 먼저 남기도록 한다. 확정 자료만 있을 때 메모를 임의로 추가하지 않는다.

## 본문 구성

기본 발표자는 `18팀 인공지능 해리`, 파트는 자료의 파트명이며 없으면 인공지능이다. 사용자 지정 발표자·파트를 인사와 마무리에 일관되게 반영한다.

기본 인사는 `안녕하세요. 18팀 인공지능 해리입니다. 인공지능 파트 주간 브리핑 드리겠습니다.`이다.
진행 상황 → 핵심 주제 3개 → 추가 사항 → 마무리 순서로 구성한다. 자료에 주제가 적거나 사용자가 수·순서를 정했으면 그대로 따른다. 추가 사항이 없으면 만들어 넣지 않는다.

각 주제는 `첫 번째는…`, `두 번째는…`, `세 번째는…`로 전환하고 문제와 대응·현재 상태를 연결해 설명한다. 슬라이드 목록을 그대로 낭독하지 않는다. 같은 주제의 문장은 한 문단으로 묶으며 문장마다 줄을 끊지 않는다.
기본 마무리는 `이상 인공지능 파트 주간 브리핑 마치겠습니다. 감사합니다.`이다.

자료에 없는 사실·사용자 사례·원인·계획·완료 상태를 추가하지 않는다. 로컬 확인, 배포 전, 추정 원인, 합의 전, 향후 계획 등의 제한은 축약 후에도 남긴다. 원문과 충돌하는 새 정보가 들어오면 그 정보를 자료에 먼저 반영하도록 연결하되 사용자가 지정한 수정 범위를 지킨다.

## 시간 제한 — 최우선

인사·진행 상황·전환·핵심 내용·추가 사항·마무리를 모두 포함한 낭독 본문을 2~3분 이내로 작성한다. **편집 목표는 2분 20초~2분 40초**이며 3분까지 여유를 둔다.

1. 본문을 쓴 뒤 숫자·단위·영문 약어를 실제 읽을 발음으로 풀어 쓴 계산용 사본을 만든다. 예: `API 3초` → `에이피아이 삼 초`. 제목·시간 안내·질의응답 메모는 계산에서 제외한다.
2. 공백·문장부호 제외 글자 수 N을 실제로 센다. 기본 추정은 `N ÷ 330 × 60 + 15초`, 느린 가정은 `N ÷ 300 × 60 + 20초`이다. 이 속도와 휴지는 편집용 가정이지 연구로 검증된 평균이나 개인 발화 보장이 아니다. 리허설 실측이나 사용자 지정 속도·휴지가 있으면 그것을 우선한다.
3. 가능하면 이 스킬 폴더 기준 `python3 scripts/estimate_time.py < /tmp/narration.txt`로 계산한다. 파일에는 발음으로 풀어 쓴 낭독 본문만 넣는다. 도구를 사용할 수 없으면 같은 식으로 계산하고 추정치임을 표시한다.
4. 기본 추정 140~160초와 느린 가정 180초 이하를 함께 점검한다. 초과하면 반복 요약, 구현 세부사항, 중요도 낮은 추가 사항부터 줄여 **다시 계산**한다. 사실·검증 범위·미해결 표시는 남긴다.
5. 3분 안에 담기 어려운 내용은 `시간이 남을 때 / 질의응답용`으로 분리한다. 이 부분은 기본 낭독 시간에 포함되지 않으며 읽으면 시간이 늘어난다고 짧게 표시한다.
6. 근거가 충분한데 지나치게 짧으면 화면 본문과 발표자 메모 안의 문제·대응 연결을 보충한다. 연결 작성에서 화면 요약만 짧다는 이유로 근거 부족이라 판단하지 않는다. 근거가 적으면 짧은 원고를 유지하고 예상 시간을 솔직하게 표시한다. 2분을 채우기 위해 사실이나 반복 설명을 만들어내지 않는다.

예상 시간은 본문 아래 한 줄로 쓴다: `예상 약 2분 31초(발음 기준 750자, 분당 330자 + 휴지 15초). 느린 가정 약 2분 50초(분당 300자 + 20초). 실제 시간은 발화 속도에 따라 달라집니다.` 실제 계산값으로 대체하며 목표 시간을 측정값처럼 쓰지 않는다.

## 부분 수정과 출력 전 점검

- 사용자가 일부만 수정하거나 나머지를 확정하면 요청 문단만 교체한다. 전체 반환 요청이면 나머지는 글자 단위로 유지한다. 기준 원본이 없으면 요청한다.
- 자료도 수정하는 요청이면 먼저 갱신한 자료·메모를 기준으로 해당 문단을 수정한다. 이전 자료의 이미 수정된 위치를 갱신 필요라고 안내하지 않는다.
- 수정한 문단만이 아니라 **전체 본문 시간**을 다시 계산한다. 시간 안내는 본문 밖에 갱신한다. 확정 영역 때문에 초과를 해소할 수 없으면 요청 영역만 줄이고 남은 초과와 추가 축약이 필요한 위치를 알린다. 확정된 다른 문단을 임의로 수정하지 않는다.
- 같은 자료의 다른 요약이나 스크립트의 확정 문단과 상태가 충돌하면 그 위치를 본문 밖에서 알린다. 불일치가 있는 결과를 검증 완료라고 표시하지 않는다.
- 자료와 스크립트의 수치·구현·테스트·배포·추정·합의·계획을 대조한다. 새 주장은 제거한다. 서두·전환·마무리·문단 묶음·계산 범위도 확인한다.

기본 출력은 `발표 스크립트` 아래 낭독 문단, 그 아래 예상 시간 한 줄이다. 필요한 경우에만 질의응답용 메모와 실제 불일치 안내를 덧붙인다.
