# Weekly Brief · 주간 발표

주간 기록을 다른 파트 개발자와 PM이 이해할 발표 자료와 2~3분 낭독 스크립트로 정리합니다.
자료를 확정한 뒤 말투와 분량만 조정할 수 있도록 두 스킬로 나눴습니다.
둘 다 요청하면 화면용 자료와 필요한 발표자 메모를 작성한 뒤, 두 내용을 근거로 스크립트를 작성합니다.
메모는 화면 공유에서 제외하며 원본의 검증 조건·사례 등 요약에서 빠진 근거만 남깁니다.
확정 자료만 제공하면 메모나 원본 사실을 임의로 추가하지 않습니다.

| 상황 | 스킬 | 결과 |
| --- | --- | --- |
| 러프한 기록에서 주제 선정·자료 작성 | `$weekly-material` | 후보와 추천 3개 또는 화면용 마크다운 |
| 확정된 자료에서 낭독문 작성·수정 | `$weekly-script` | 문단형 스크립트, 예상 시간, 필요시 질의응답용 메모 |

## 입력 프롬프트

주제를 고르기 전에는 기록만 붙여 넣습니다. 후보는 `항목: 작업·문제·대응 요약`으로 나오며,
배포·사용자 영향, 협업, 기술 개선, 교훈을 기준으로 추천합니다. 선택할 때까지 최종본은 작성하지 않습니다.

```text
$weekly-material
아래 주간 기록에서 발표 후보를 정리하고 핵심 3개를 추천해줘.
[작업 기록, 협업 대화, 트러블슈팅 메모]
```

추천을 받은 뒤:

```text
1, 2, 4번으로 정했어. 발표 자료와 2~3분 스크립트까지 작성해줘.
```

주제가 정해졌거나 바로 최종본이 필요할 때:

```text
$weekly-material
인공지능 파트. 아래 기록에서 핵심 3개를 골라 자료와 스크립트까지 바로 최종본으로 작성해줘.
[기록]
```

스크립트만 필요할 때:

```text
$weekly-script
아래 확정 자료로 2~3분 스크립트 작성해줘.
발표자는 18팀 인공지능 해리야.
[발표 자료]
```

부분 수정:

```text
자료와 스크립트의 두 번째 주제만 수정해줘.
로그 추가는 구현 완료했고 재현 테스트는 아직이야. 나머지는 확정이야.
```

다른 파트·발표자도 지정할 수 있습니다. 기본은 인공지능 파트, `18팀 인공지능 해리`입니다.
자료만 수정하면 스크립트를 자동 변경하지 않고, 불일치가 생길 때 갱신 필요를 알립니다.

## 결과 예시

가상 입력: `검색 지연은 캐시 문제로 추정. 재현 못함. 다음 주 로그 추가 예정.`

자료의 해당 부분:

```markdown
### 어떤 어려움이 있었나? - 2. 검색 지연 원인 확인
- 검색 지연 원인을 캐시 문제로 추정하고 있으나 재현하지 못했습니다.

### 어떻게 해결할 예정인가?
- 다음 주 로그를 추가할 예정입니다.
```

스크립트의 해당 문단:

> 두 번째는 검색 지연입니다. 캐시 문제로 추정하고 있지만 아직 재현하지 못해 원인을 확정하지 못했습니다. 다음 주에는 로그를 추가할 예정입니다.

위 문단은 전체 2~3분 원고가 아닌 부분 예시입니다. 미해결 문제를 해결 완료로 바꾸지 않습니다.

## 시간 산정

전체 낭독 본문에서 숫자·영문 약어를 실제 발음으로 풀어 쓴 뒤 공백·문장부호를 제외한 글자 수를 셉니다.
기본 계산은 `글자 수 ÷ 330 × 60 + 휴지 15초`, 느린 가정은 `글자 수 ÷ 300 × 60 + 휴지 20초`입니다.
이는 이 플러그인의 편집용 가정이며 검증된 개인 발화 속도나 실제 시간 보장이 아닙니다.
기본 140~160초, 느린 가정 180초 이하를 목표로 하고 실제 리허설 값이 있으면 우선합니다.
짧은 자료는 사실을 보태서 늘리지 않으며, 긴 자료는 세부 내용을 `시간이 남을 때 / 질의응답용`으로 분리합니다.

```bash
python3 weekly-brief/skills/weekly-script/scripts/estimate_time.py < /tmp/narration.txt
```

입력 파일에는 인사·전환·추가 사항·마무리를 포함한 **낭독 본문만** 넣습니다.
제목·예상 시간 안내·질의응답용 메모는 제외합니다. 발음 변환은 작성자가 수행하며 도구는 자동 변환하지 않습니다.
Python 표준 라이브러리만 사용합니다. 도구 없이 같은 식으로 계산할 수도 있습니다.

## 로컬 사용

기존 저장소 방식에 따라 스킬을 직접 연결할 수 있습니다. 저장소 루트에서 실행하며,
목적지에 같은 이름이 있다면 먼저 확인합니다.

```bash
mkdir -p ~/.codex/skills
ln -s "$PWD/weekly-brief/skills/weekly-material" ~/.codex/skills/weekly-material
ln -s "$PWD/weekly-brief/skills/weekly-script" ~/.codex/skills/weekly-script
```

이는 개별 스킬 연결이며 플러그인 설치는 아닙니다. 플러그인 소스는 `weekly-brief/` 전체입니다.
개인 마켓플레이스·설치 설정은 이 저장소 작업에서 변경하지 않습니다. API 키나 별도 서버는 필요하지 않습니다.
기본 출력은 대화 내 마크다운이며 저장·게시·발송은 별도 요청 범위입니다.
