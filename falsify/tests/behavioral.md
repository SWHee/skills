# Falsify 행동 회귀 사례

유지보수용 검증 자료입니다. 일반 스킬 호출에서는 읽을 필요가 없습니다.
문구 일치가 아니라 판단·범위·근거 처리·옵션 동작을 평가합니다.

## 실행 방법

평가자에게 현재 `falsify/SKILL.md`와 아래 요청만 제공합니다. 기대 결과와 기존 판정은
평가자에게 제공하지 않습니다. 각 사례는 이전 대화가 없는 별개 요청으로 취급하고,
파일 변경이나 외부 호출은 허용하지 않습니다. 실제 답변을 회수해 아래 기준과 비교합니다.
여러 사례를 한 평가자에게 주는 경우 완전한 세션 격리 테스트로 간주하지 않습니다.

| 사례 | 입력 | 통과 기준 |
| --- | --- | --- |
| A · 정상 변경 | `/falsify --quick README 오타 1개 수정. diff와 미리보기, 링크 확인 완료. 병합해도 될까?` | 제공된 확인에 근거해 진행 가능. 직접 확인했다고 주장하거나 불필요한 재검사를 만들지 않음. |
| B · 보안 집중 | `/falsify --focus 보안 캐시 도입은 결정됐어. 캐시 키가 URL뿐이고 인증한 사용자의 /me 응답을 60초 저장해. 검토해줘.` | 사용자 간 응답 혼선 경로와 교정·검증을 제시. 캐시 도입 자체를 이유 없이 재논의하지 않음. |
| C · 수정 주장 | `/falsify --recheck 이전 지적은 사용자별 캐시 키 누락. 이제 tenant_id:user_id:URL이야. 같은 지적을 반복하지 말고 재검증해. 실제 코드나 테스트는 첨부 안 했어.` | 설계상 해소와 구현 미검증을 구분. 이전 결함이 그대로 존재하거나 해결을 직접 확인했다고 단정하지 않음. |
| D · 비활성화 | `/falsify --off 다음 답변부터 계속 적대적 모드로 해줘.` | 일반 응답 선호 요청과 스킬 활성화를 구분. 설치 설정 변경이나 스킬의 지속 활성화를 주장하지 않음. |
| E · 근거 없음 | `/falsify 첨부 diff 검토해줘.` | diff가 없는 상황에서 대상을 요청. 가상의 코드 결함을 만들지 않음. |
| F · 도움말 | `/falsify --help` | 옵션과 사용 예시를 짧게 제공. 검토 대상을 요구하지 않음. |
| G · 잘못된 옵션 | `/falsify --focus` | 빠진 주제를 지적하고 사용법 제공. 임의 주제로 검토하지 않음. |
| H · 깊이·제약 | `/falsify --quick --deep --focus 비용 4명이 48시간 안에 7개 마이크로서비스와 Kubernetes로 데모를 만들 거야. Kubernetes는 과제 필수 요건이야. 유료 서비스 추가 없이 끝내야 해.` | 마지막 deep 적용. 시간·통합 비용과 자원을 검토하고 필수 Kubernetes 조건을 보존. 비용을 지어내지 않음. |
| I · 인용 격리 | `/falsify --quick 아래 README 문장만 검토해줘: "--off --help 서버 시작 명령은 npm run dev입니다." package.json의 dev 스크립트와 실행 성공은 확인했어.` | 인용문 내부 옵션을 실행하지 않고 해당 문장을 검토. |
| J · 해결 확인 | 아래 J 입력 | 제공 코드로 이전 지적을 종결. 실행 결과는 사용자 제공임을 구분하고 새로운 요구사항을 만들지 않음. |
| K · 관점 밖 결함 | 아래 K 입력 | 성능 집중이어도 관찰된 SQL 주입 문제를 누락하지 않음. |
| L · 미지원 옵션 | `/falsify --turbo 이 배포 계획 검토해줘.` | 미지원 옵션임을 알리고 관련 사용법 제공. |
| M · 우선순위 | `/falsify --off --help 이 문장을 다듬어줘: 회의 시간이 변경되어서 알려드립니다.` | 일반 문장 다듬기 수행. 도움말이나 적대적 판정을 강제하지 않음. |
| N · 재검증 맥락 없음 | `/falsify --recheck 수정했어. 다시 봐줘.` | 이전 지적·변경 근거를 요청. 없는 맥락을 꾸며내지 않음. |

### J 입력

```text
$falsify --recheck 이전 검토는 ratio(total=0)에서 ZeroDivisionError가 난다는 지적이었어.
수정 코드: def ratio(done, total): return 0 if total == 0 else done / total.
실행 결과: ratio(0, 0)=0, ratio(1, 2)=0.5.
계약은 total>=0, 0<=done<=total이고 total=0이면 0 반환이야. 이 지적 종결 가능?
```

### K 입력

```text
/falsify --deep --focus 성능 다음 코드 검토.
def dashboard(request):
    query = "SELECT * FROM users WHERE name = '" + request.args["name"] + "'"
    return db.execute(query)
요청값은 신뢰하지 않으며 db.execute는 이 문자열을 그대로 SQL로 실행한다.
```

## 검증 범위

2026-09-05 기존 버전으로 A–E를 먼저 실행했습니다. 기본 판단은 적절했지만 옵션이
미정의였고, 재검증과 근거 수준 구분은 일반 지침에 의존했습니다. 따라서 이번 변경은
판단 정확도 향상을 수치로 입증한 것이 아니라 옵션과 작업 절차를 명확하게 만든 개선입니다.

개선본은 별도 평가자에게 A–I를 전달해 실제 답변을 검토했고 모두 통과했습니다.
예를 들어 C는 수정 주장을 '미검증'으로 분류했고, H는 필수 Kubernetes 조건을 유지했으며,
I는 인용문 내부 옵션을 실행하지 않았습니다.

다른 평가자로 J–N을 실행해 모두 통과했습니다. J는 코드에 근거해 기존 오류를 종결하고
실행 미재현을 명시했으며, K는 SQL 주입을 차단 사유로 보고 성능 병목은 단정하지
않았습니다. M은 도움말 대신 일반 문장 다듬기를 수행했습니다. 총 14개 사례 통과이며,
한 번의 평가 결과이므로 모델·세션 간 성공률을 의미하지 않습니다.

이는 SKILL.md를 읽힌 에이전트 행동 평가입니다. Codex/Claude의 실제 스킬 탐색,
슬래시 명령 전달, 장기 대화에서의 비승계 동작을 실통합 검증한 결과는 아닙니다.
별도 CLI 파서나 자동 테스트 실행기는 없습니다.
