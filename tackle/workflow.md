# Tackle 사용 흐름

독립 스킬 하나로 사용한다. `$tackle` 뒤에 문제와 원하는 작업 범위를 적는다. 이 문서는 사용자용 안내이며 에이전트의 실행 규칙은 `SKILL.md`에 있다.

```mermaid
flowchart TD
    A[요청과 기존 맥락 확인] --> B{코드 변경 의도}
    B -->|조사·정리 요청| C[조사 범위로 진행]
    B -->|직접 구현·개선 요청 또는 기존 위임| D[수정·검증 범위로 진행]
    B -->|모호함| Q[코드 수정까지 원하는지 질문]
    Q -->|답변 전| R[독립적인 읽기 전용 조사]
    Q -->|답변| B
    C --> E[필요한 단계에서 문제 정의·조사]
    D --> E
    E --> F[증거 취합·추천과 대안]
    F --> G{새로운 사람의 판단 필요?}
    G -->|필요| H[우선순위·비용·위험 선택]
    H -->|방향 선택| I{현재 실행 범위}
    G -->|기존 결정·위임으로 충분| I
    H -->|진행하지 않음| P[보류·재개 조건 기록]
    I -->|조사까지| J[조사 결과 제공·종료]
    I -->|수정까지| K[작은 변경·검증]
    K --> L{성공 기준 확인}
    L -->|충족| M[해결 확인·범위 기록]
    L -->|실패·새 근거 있음| E
    L -->|관측 불가·진행 제한| N[미해결 또는 효과 미확인·다음 확인]
```

예시:

- `$tackle 화면 로딩이 느려요.` → 코드 수정 의도 질문, 독립적인 조사 진행.
- `$tackle 로딩 성능을 개선해줘.` → 필요한 조사부터 코드 변경·검증까지.
- `$tackle 로딩 성능 개선 방안을 비교해줘.` → 판단 자료까지, 코드 변경 없음.
- `$tackle 앞서 선택한 방안으로 구현해줘.` → 기존 근거를 재사용해 수행·검증.

이전 HTML 다이어그램은 초기 설계안이다. 위 흐름에는 이후 합의한 모호한 요청의 실행 범위 확인이 반영돼 있다.
