# Clear Message · 협업 메시지 정리

받은 말에서 핵심과 대응할 내용을 찾고, 보낼 말은 상대가 이해할 수 있는 순서로 정리합니다.
개인 작업 중 협업 맥락을 파악하는 부담을 줄이기 위한 두 스킬입니다.

긴 메시지를 짧게 만드는 데서 끝내지 않습니다. 질문·부탁·보고·제안을 구별하고,
보낼 때는 작성자의 의도와 확실성을 유지한 채 전달 순서를 정리합니다.

| 상황 | 선택할 스킬 | 결과 |
| --- | --- | --- |
| 상대의 복잡한 말을 이해하고 싶을 때 | **받은 말 이해하기** · `$read-message` | 핵심 → 답변·작업 요청 → 상황 → 제안·빈칸 |
| 내 초안을 상대가 이해하기 쉽게 보내고 싶을 때 | **보낼 말 정리하기** · `$write-message` | 목적과 요지 → 실제 요청 또는 결론 → 필요한 배경 |

## 호출

스킬을 선택하고 원문을 그대로 붙여 넣으면 됩니다. 역할·톤·형식을 미리 채울 필요가 없습니다.
이름이 섞인 단체 대화라면 `나는 민수`처럼 한 줄을 추가하면 요청 대상을 구분하기 쉽습니다.

```text
$read-message
[상대에게 받은 원문]
```

```text
$write-message
[내가 보내려던 초안]
```

원문을 처리하는 현재 에이전트 외에 별도 서버나 모델 호출을 추가하지 않습니다.
자동 발송, 프로젝트 파일 검색, 기술 주장 검증은 기본 기능에 포함하지 않습니다.

## 받은 말: 상단만 읽어도 핵심과 대응 여부

```text
핵심: 팀원은 검색 API에 캐시를 추가하자고 제안했으며, 테스트 수정은 남아 있습니다.
대응: 답변 있음 · 작업 있음 — 캐시 적용 부탁은 수락 여부가 확인되지 않았습니다.

대응할 내용
- [답변] 캐시 유효기간을 5분으로 두는 안에 대한 의견 알려주기.
- [작업 부탁] 검색 API에 캐시 적용 요청. 담당 범위·수락 여부는 미확인.

상황
- 팀원은 캐시를 적용하면 반복 조회가 줄어들 것으로 예상합니다.
- 테스트는 아직 수정하지 않았다고 합니다.

제안·논의
- 캐시 유효기간을 5분으로 두자는 제안이며, 합의 여부는 드러나지 않습니다.
```

문서의 이름·상황·메시지는 사용법을 보여주기 위한 가상 예시입니다.
`테스트 미수정`을 사용자에게 맡긴 작업으로 바꾸지 않습니다.
짧은 보고라면 아래 두 줄로 끝납니다.

```text
핵심: 발신자는 배포를 완료했다고 보고했으며 내일 오전까지 로그를 확인할 계획입니다.
대응: 답변 없음 · 작업 없음 — 제공된 메시지에 요청은 없습니다.
```

`요청 없음`은 이전 약속까지 포함해 아무것도 하지 않아도 된다는 뜻이 아닙니다.
요청이 분명하지만 내용이 빠졌다면 `작업 있음 — 내용 불명확`으로 표시합니다.

## 보낼 말: 복사할 본문부터

초안:

> 테스트는 아직 못 고쳤는데 변경은 재시도 부분이에요. 일시 오류 때 한 번 더 하게 했어요. 혹시 내일 오전까지 PR 봐주실 수 있나요? 타임아웃 쪽이 걱정돼서요.

출력 예시:

> 일시적인 오류가 나면 한 번 더 시도하도록 재시도 로직을 변경했어요.
> 내일 오전까지 PR을 검토해주실 수 있을까요? 특히 타임아웃 처리를 봐주시면 좋겠어요.
>
> 테스트는 아직 수정하지 못했어요.

요청이 없는 보고에는 새로운 부탁을 붙이지 않습니다. 의견·추측·예상은 그 상태로 보존합니다.
긴 초안은 주제별로 나누며, 목적에 따라 다음 순서를 적용합니다.

| 목적 | 자연스러운 본문 순서 |
| --- | --- |
| 질문·부탁 | 필요한 맥락 → 질문·부탁 → 이유·조건 |
| 진행·완료 공유 | 상태·결과 → 영향·남은 일 → 원문에 있는 다음 계획 |
| 제안 | 제안 → 선택지·이유 → 원문에 있는 의견 요청 |

기한이나 대상이 충돌하면 본문에 구체적인 확인 표시를 남기고, 본문 아래 `보내기 전 확인`을 분리합니다.
그 외에는 해설 없이 메시지 본문 하나만 반환합니다. 출력 구조는 초기안이며 사용 피드백에 따라 조정합니다.

## 로컬에서 사용

이 폴더는 `.codex-plugin/plugin.json`과 두 스킬을 포함한 플러그인 소스입니다.
사용자의 설치 상태와 무관하게 사용할 수 있는 소스입니다. 별도 API 키나 외부 서비스 연결은 필요하지 않습니다.

기존 저장소의 개인 스킬 연결 방식을 쓰려면 저장소 루트에서 다음을 실행합니다.
아래 두 목적지에 이미 파일이나 링크가 있다면 덮어쓰지 말고 먼저 확인하세요.

```bash
mkdir -p ~/.codex/skills
ln -s "$PWD/clear-message/skills/read-message" ~/.codex/skills/read-message
ln -s "$PWD/clear-message/skills/write-message" ~/.codex/skills/write-message
```

새 작업에서 두 스킬을 선택할 수 있습니다. 이 방법은 스킬을 직접 연결하는 것이며 플러그인 설치는 아닙니다.
다른 사용자에게는 `clear-message/` 폴더 전체와 이 사용 안내를 함께 공유할 수 있습니다.

## 사용 범위

원문을 넣는 AI 서비스의 데이터 처리 정책은 그대로 적용됩니다. 공유용 예시에는 실제 대화,
접근 토큰, 비공개 링크와 개인 정보를 포함하지 마세요.
이 플러그인은 문장 구조를 정리하며 사실 검증이나 상대의 숨은 의도 판단을 보장하지 않습니다.
보낼 메시지는 요청 대상·기한·약속이 원래 의도와 맞는지 확인한 뒤 사용하세요.

## 동작을 확인할 사례

아래는 반복 평가에 사용할 입력과 통과 기준이며, 독립 모델 평가나 사용자 실험 결과가 아닙니다.
문구 일치보다 의미·요청 대상·확실성 보존을 확인합니다.

| 스킬 | 입력 | 통과 기준 |
| --- | --- | --- |
| read | 배포 완료했습니다. 참고해주세요. | 완료 보고로 정리. 답변·작업 요청 없음 |
| read | 가능하면 STT 구현 부탁드려도 될까요? | 조건부 작업 부탁 보존. 수락·담당 확정으로 바꾸지 않음 |
| read | PR 검토하고 결과 알려주세요. | 검토→답변 한 항목. 답변·작업 모두 있음 |
| read | 아까 얘기한 방식으로 오늘까지 부탁드려요. | 작업 요청 있음. 작업 내용·방식 불명확. 날짜를 추측하지 않음 |
| read | 나는 민수. 지수님, 로그 확인해주세요. | 지수에게 향한 요청. 민수의 작업으로 옮기지 않음 |
| read | A: 오늘 배포해주세요. B: 장애가 있습니다. A: 배포 요청 취소할게요. | 배포 요청 철회 반영. 활성 배포 요청으로 표시하지 않음 |
| read | 테스트는 못 고쳤어요. 이거 좀 애매하네요. | 미완료·우려 보고. 해결 작업을 독자에게 배정하지 않음 |
| write | 배포 했어요. 로그는 내일 볼게요. | 본문만 반환. 확인 부탁·새로운 기한·다른 담당 추가 없음 |
| write | 오늘 가능할 것 같고요, 테스트는 아직이에요. | 예상과 미완료 보존. 오늘 완료 약속으로 바꾸지 않음 |
| write | A는 0.5, B는 0.7이었어요. B가 나은 걸까요? | 수치와 질문 유지. B의 우수성을 단정하지 않음 |
| write | 민수가 “제가 테스트할게요”라고 했어요. | 민수의 계획을 작성자의 약속으로 바꾸지 않음 |
| write | 기한은 월요일이에요. 금요일이 마감이에요. | 기한을 임의 선택하지 않음. 본문 표시와 별도 확인 사항 |

구조 검증은 저장소에서 쓰는 기본 검증기를 사용합니다.

```bash
python3 ~/.codex/skills/.system/plugin-creator/scripts/validate_plugin.py clear-message
python3 ~/.codex/skills/.system/skill-creator/scripts/quick_validate.py clear-message/skills/read-message
python3 ~/.codex/skills/.system/skill-creator/scripts/quick_validate.py clear-message/skills/write-message
```

초기 사용자 평가에서는 3명 이상이 서로 다른 메시지를 읽고 쓰는 상황에 적용합니다.
받는 쪽은 맥락 파악 시간·요청 누락·결정 오해를, 보내는 쪽은 편집 시간·의도 변경·수신자의 추가 확인 질문을 봅니다.
일반 AI 요청과 같은 입력 조건으로 비교하고, 같은 메시지를 반복해서 읽어 생기는 학습 효과를 피합니다.
